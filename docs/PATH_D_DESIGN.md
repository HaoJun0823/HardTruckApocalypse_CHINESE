## 1. 问题

引擎字形表 `Font+0x40` 是 **256 项、按单字节索引**（IDA 实证，hta.exe）：

```asm
0x6865A6  8B 57 40        mov     edx, [edi+40h]   ; edx = 字形表基址
0x6865A9  0F B6 EB        movzx   ebp, bl          ; ★ 只读 1 字节
0x6865AC  03 ED           add     ebp, ebp
0x6865AE  03 ED           add     ebp, ebp         ; ebp = byte*4
0x6865B0  8B 04 2A        mov     eax, [edx+ebp]   ; glyph = table[byte]
```

扣掉 ASCII / 标点 / 西里尔，能腾给汉字的只剩约 72 个。完整汉化需要 1000~3000 个不同汉字。

参考项目 `MajestyIIExtend` 能支持 24163 个字形，是因为它的引擎有一个独立的
「字节流→槽号」映射函数，槽号本来就是完整整数。**本引擎没有这个函数**，
查表内联在绘制循环里，只能改循环本身。

## 2. 索引字节序（改任何东西前先读这一节）

| 类型 | 编码 | 16 位索引 | 范围 |
|---|---|---|---|
| ASCII / 拉丁 | 单字节 `c` | `c` | `0x0000~0x00FF` |
| 汉字 | GBK 双字节 `[b1][b2]` | **`(b1<<8)|b2`** | `0x8140~0xFEFE` |

> ★ 注意是 `(b1<<8)|b2`，也就是 **GBK 原值本身**，**不是** `b1|(b2<<8)`。
>
> 早期设计文档写成 `b1|(b2<<8)`，与实现差一次字节序颠倒。`FillCjk` 与 P4
> 必须严格一致，否则整屏错字。这条历史上写反过，是最容易复发的坑。

- 两组索引不重叠：前 256 项沿用引擎原有的 Latin/西里尔字形，位置不变。
- b1 天然落在 `0x81~0xFE`，**永远不会**是 `0x23/0x24/0x26/0x40/0x7C`
  这些被绘制路径劫持的转义字节 ⇒ 双字节序列不会被误判为转义。

## 3. Font 对象布局

依据：析构 `sub_8B67A0`、构造 `sub_8B6740`、绘制 `0x6865A6`、绑定 `0x6868CB`。

| 偏移 | 类型 | 含义 |
|---|---|---|
| `+0x00` | 小字符串 | 字体名（SSO，16 字节） |
| `+0x18` | f32 | 字号 height |
| `+0x2C` | vector | 图集页数组（首/末/容 `+0x30/+0x34/+0x38`） |
| `+0x40` | vector | **字形表**（首/末/容 `+0x40/+0x44/+0x48`），元素是 `texId`/字形指针 |

**页数组的元素是 `texId`（int），不是指针**（`0x8B8542` 传的是数组里存的整数本身）。

## 4. 字形结构（48 字节 = `kGlyphSize`）

三重核实：`sub_8B80B0` 逐字段初始化 + `sub_8B6280` finalize + `fonts.xml` 实测数据。

| 偏移 | 类型 | 含义 |
|---|---|---|
| `+0x00` | u8 | 字符码（引擎只拿它做字典校验） |
| `+0x04/+0x08/+0x0C` | f32 | abc[0..2] |
| `+0x10` | i32 | **图集页号** |
| `+0x14/+0x1C` | f32 | u0 / u1 |
| `+0x18/+0x20` | f32 | v0 / v1 |
| `+0x24` | f32 | 像素宽 |
| `+0x28` | f32 | 像素高 |
| `+0x2C` | f32 | 推进量（advance） |

> finalize (`sub_8B6280`) 只遍历 `off_A05E38` 这个**单字节**字符集，
> 永远不会碰到我们的汉字 ⇒ `+0x24/+0x28/+0x2C` 必须自己填。

## 5. 实际架构（⚠ 与早期设想不同）

### 5.1 为什么不是「原地 16 位编码」

早期设想：把 P1/P4 的 `movzx` 改成读 16 位，几字节内原地解决。**没有采用**，原因：

1. 补丁点只有 9~18 字节，放不下完整的双字节判定 + 表选择逻辑；
2. 需要按 `Font*` 选表（见 §6），而 `Font*` 只存在于栈上，寄存器里拿不到；
3. 引擎要求「除 `eax/ecx/ebp` 外寄存器原样保留」（见 §7），C++ 助手做不到。

### 5.2 实际方案：call 注入 + naked 助手

| 补丁 | 地址 | 覆盖 | 作用 | 原始字节 |
|---|---|---|---|---|
| **P4** | `0x6865A6` | 18 字节 | 主查表（含 GBK 双字节 + 按 Font* 选表） | `8B 57 40 0F B6 EB 03 ED 03 ED 8B 04 2A 85 C0 8D 0C 2A` |
| **P4b** | `0x686A26` | 10 字节 | 第二处查表（提供 advance） | `8B 44 24 34 8B 48 40 8B 04 29` |
| **P5** | `0x686A52` | 9 字节 | 主遍历推进（双字节 +2） | `0F 57 C0 83 C6 01 83 C7 01` |
| **P2** | `0x68620D` | 5 字节 | 预扫遍历 A | `83 C7 01 EB B5` |
| **P3** | `0x686221` | 5 字节 | 预扫遍历 B | `83 C7 01 EB A1` |

另有 **4 处跳转目标必须同步重定位** `0x686A55 → 0x686A52`：
`0x6864ED` / `0x686507` / `0x68658B` / `0x68659C`。

> 循环结构（IDA 确认）：循环头 `0x6864D5`，唯一前驱 `0x686A63`。
> P5 的落点 `0x686A5B` = `cmp esi,[esp+6Ch]`。

### 5.3 故意不打补丁的点

| 地址 | 原因 |
|---|---|
| **P7** `0x0044ED34`（`sub_685990` 度量遍历，3 字节） | 3 字节放不下条件判断，硬补会破坏 ASCII 度量。**后果**：中文宽度被按字节数低估，居中/右对齐会偏左，左对齐无影响。实测影响可接受，暂不改。 |
| `0x6861F2` `0x686384` | 固定索引 `0x20`（空格宽度），纯 ASCII |
| `0x686A2A` `0x686A2D` | 复用 `ebp`（= 索引×4），P4 之后自动正确 |

## 6. 每字体独立汉字表

### 6.1 为什么不能共用一张表

最初所有字号共用一张 64K 表，而后台线程是**按字号依次填充**的：
后填的字号会覆盖先填的 ⇒ 每个汉字都拿到**别的字号**的字形，
`pxW`/`pxH`/`advance` 全错 ⇒ 字号/行距错乱。

### 6.2 现在的做法

```
CjkSlot g_cjkSlots[MAX_CJK_TABLES=16];   // { void* font; uint32_t* table; volatile LONG ready; }
volatile LONG g_cjkSlotCount;
```

- 每字体一张 64K 项（256KB）表，`CjkTableEnsure(font)` 懒分配。
- 实际只用到约 10 个字号 ⇒ 约 2.5MB。
- `FillCjk` 填表前 `ready=0`，填完 `ready=1`，绘制线程不读半成品。

### 6.3 P4 里必须内联扫描，不能 call

引擎契约（§7）要求「除 `eax/ecx/ebp` 外寄存器原样保留」。
而 `bl` 只是 `ebx` 的**低字节** —— 编译器生成的循环完全可能拿 `ebx` 当计数器，
`bl` 随之被改写。于是 `pl_null` 里的 `movzx ebp,bl` 算出错误索引，整个 CJK 判据失效。

**实测**：用 `call PathD_CjkTableFor` 查表后，按钮文字**全部消失**（不是叠字，是空白）。
改为内联扫描（只用 `eax/ecx/edx` 三个已用完的寄存器）后恢复。

```asm
mov  ecx, [esp+0]          ; Font*（0x6865A2 mov edi,[esp+34h] 存进 [esp+0]）
mov  eax, offset g_cjkSlots
mov  edx, [g_cjkSlotCount]
pl_scan2:
    test edx, edx
    jz   pl_null
    cmp  [eax], ecx
    je   pl_found
    add  eax, 12           ; sizeof(CjkSlot)
    dec  edx
    jmp  pl_scan2
pl_found:
    mov  edi, [eax+4]
```

## 7. ★ 引擎契约（违反即崩）

三条硬约束，写在 `pathd.cpp` 顶部：

1. 除 `eax` / `ecx` / `ebp` 外，**所有寄存器必须原样保留**。
   `bl` 只是 `ebx` 的低字节 —— 任何 C++ 函数都可能改写它。
2. **绝不在这些助手里 `call` C++ 函数**（§6.3 有实测）。
3. P4 出口：`ebp` = 索引×4，`ecx` = 槽地址，成功时 `edx` = 字体表，
   且必须留下 `test eax,eax` 的结果给 `0x6865BD jnz`。

### 栈偏移

**一律读 ModRM/SIB 的 disp 字节，不要信 IDA 的 `stack_frame` 表。**

```asm
0x6864B1  8B 44 24 54       mov eax, [esp+54h]     ; 文本基址指针（var_9C）
0x6865A2  8B 7C 24 34       mov edi, [esp+34h]     ; Font*（var_BC）
0x686A5B  3B 74 24 6C       cmp esi, [esp+6Ch]     ; strlen（var_84）
```

经验公式：**call-entered helper 实际位移 = 引擎偏移 + 4 + 4×pushes**。

> `var_9C` **是一个指针**，必须解引用（`mov eax,[esp+54h]`），
> 直接把它当缓冲区读是错的。

## 8. 字形资源与运行时装载

### 图集页 height 编码

```
height = 500 + sizeIndex*50 + pageIndex      （pageIndex < 50）
```

`fontgen/build_cjk.py` 与 `pathd.cpp` 的 `kCjkBase/kCjkStep` **必须同步改**。
步长 50 > 单字号最大页数（实测 2330 字时 18.750 号要 19 页），否则两个字号
会编码到同一张图集。

### 包格式 `hta_chs_cjk.bin`

| 字段 | 值 |
|---|---|
| magic | `0x4B4A4348` |
| version | 1 |
| header | 48 字节（`<6I`） |
| code table | `glyphCount` × uint16 |
| size records | `<fIIIIIII`，位于 `48 + glyphCount*2` |
| cell indices | `glyphCount` × uint32 |

实测：字号数 10，字形数 2207，图集页 512×256（DXT5，174,928 B/张，共 89 张）。

## 9. 踩过的坑（按代价排序）

| 现象 | 根因 | 教训 |
|---|---|---|
| 文字**全部消失** | P4 里 `call` C++ 查表，编译器改写 `bl` | 见 §6.3，助手内只能用裸汇编 |
| 崩 `0xC0000005` @ `0x6865C7` | 字形池扩容时 `VirtualFree` 旧池，而表里存的是**原始地址** | 扩容**永不释放**旧池（泄漏 ~2MB 换指针永久有效） |
| 崩 @ `0x6B286656` | P4b 自行解引用 `var_BC` 取 `Font*`，但 **flush 路径根本不经过 P4** | 该路径 `var_BC` 不是有效 `Font*`；P4b 改为**只读缓存 + 字符校验** |
| 英文字全叠一起 | P4b 是 `xor eax,eax` 空桩，advance 恒为 0 | P4b 必须交出真实字形指针 |
| 汉字完全不显示 | P4 栈偏移按 `+0xC` 算（漏了 call 的 4 字节返回地址）；且把指针当缓冲区读 | 见 §7 栈偏移 |
| 字号/行距错乱 | 10 个字号共用一张表，后填覆盖先填 | 见 §6 |
| 补丁写了却没生效 | 单次 `memcpy` 与引擎自修改竞争 | 必须挂起全部线程 + 确认 EIP 不在改写区间；**挂起期间绝不 `Logf`** |
